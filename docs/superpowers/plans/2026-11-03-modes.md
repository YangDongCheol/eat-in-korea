# 모드 구조 + 집밥 + 다이어트 + 이전 앱 통합 (1단계) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eat in Korea에 모드 선택 첫 화면, 집밥 방식(레시피 연결), 한국어 화면의 네이버 지도, 다이어트 모드("부담 적은 메뉴")를 넣고, 이전 앱(what-to-eat)을 새 앱으로 통합하는 정리 작업을 한다.

**Architecture:** 기존 구조 그대로(일반 `<script>` 전역, 빌드 없음). 모드는 `modes.js`의 설정(질문 목록 + 후보 조건)이고, 질문 화면·추천·결과·기록 코드는 모든 모드가 함께 쓴다. `answers.mode`는 `answers.way`(식당/배달/집밥)로 이름이 바뀌고, 메뉴에 `ways`와 `light` 필드가 더해진다.

**Tech Stack:** HTML, CSS, 바닐라 JS, localStorage, Service Worker. 테스트 `node run-tests.js`(현재 PASS 66/66), 정적 서버 `python -m http.server <포트>`.

**Spec:** `docs/superpowers/specs/2026-11-03-modes-design.md` (본 설계 `2026-11-03-eat-in-korea-design.md`, 추가분 `2026-11-03-ko-delivery-design.md`).

## Global Constraints

- 새 외부 라이브러리·빌드 도구·서버 없음. 스크립트 순서 `strings.js`, `menus.js`, `modes.js`, `logic.js`, `app.js`. 줄바꿈은 LF(`.gitattributes`가 있다; 파일을 쓴 뒤 `file <이름>`이 CRLF를 말하면 안 된다). 커밋 메시지 끝에는 시스템이 지정한 Co-Authored-By 줄을 붙인다.
- `answers`: `{ restrictions: string[], spice: "none"|"mild"|"hot", feel: "hearty"|"light"|"any", way: "dine"|"delivery"|"home" }`, `DEFAULT_ANSWERS = { restrictions: [], spice: "none", feel: "any", way: "dine" }`. `answers.mode` 키는 더 이상 없다.
- 모드 설정(`modes.js`, 정확히): `const MODES = { meal: { labelKey: "modeMeal", descKey: "modeMealDesc", questions: ["way", "restrictions", "spice", "feel"], pool: (m) => true }, diet: { labelKey: "modeDiet", descKey: "modeDietDesc", questions: ["way", "restrictions", "spice"], pool: (m) => m.light === true } };` 첫 화면 카드 순서는 `Object.keys(MODES)`.
- 지도 주소(정확히): `mapsUrl(menu, lang)` — `lang === "ko"`면 `"https://map.naver.com/p/search/" + encodeURIComponent("근처 " + menu.ko)`, 그 외·생략이면 `"https://www.google.com/maps/search/?api=1&query=" + encodeURIComponent(menu.ko + " 식당")`.
- 레시피 주소(정확히): `recipeUrl(menu, lang)` — `"https://www.youtube.com/results?search_query=" + encodeURIComponent(q)`, `q`는 `ko` → `menu.ko + " 레시피"`, `zh` → `menu.name.zh + " 食谱"`, 그 외 → `menu.name.en + " recipe"`.
- 메뉴 필드: `ways: string[]`(`"dine"`, `"delivery"`, `"home"` 중, `"dine"`은 항상 포함), `light: boolean`. 기존 태그·설명은 바꾸지 않는다. `ways`가 없는 메뉴는 `["dine"]`으로 본다(`allowed`에서만).
- 화면 문구 키 55개(현재 46개 + 새 키 9개), 이름 바꿈: `qMode`→`qWay`, `modeDine`→`wayDine`, `modeDelivery`→`wayDelivery`(값 그대로). 새 키와 값 (en / zh / ko):
  - `wayHome`: `Cook at home` / `在家做` / `집밥`
  - `modeMeal`: `Meal` / `正餐` / `식사`
  - `modeDiet`: `Diet` / `轻食` / `다이어트`
  - `modeMealDesc`: `Pick a dish that fits you` / `挑一道适合你的菜` / `나에게 맞는 메뉴를 골라줘요`
  - `modeDietDesc`: `Only lighter dishes` / `只推荐比较清淡的菜` / `부담 적은 메뉴만 골라줘요`
  - `pickMode`: `Choose a mode` / `选择模式` / `모드를 골라 주세요`
  - `recipe`: `See a recipe` / `看食谱` / `레시피 보기`
  - `backToModes`: `Back to modes` / `返回模式选择` / `모드 선택으로`
  - `dietNote`: en 정확히 `"Light" means a dish that is usually less oily or smaller, not that it is low in calories. Every restaurant is different.` / zh `“清淡”指这道菜通常油少或分量小，不代表热量低。每家餐厅做法不同。` / ko 정확히 `"부담 적은 메뉴"는 보통 기름기나 양이 적은 편이라는 뜻이고, 칼로리가 낮다는 뜻은 아니에요. 식당마다 달라요.`
- **금지어**(대소문자 무시, 모든 문구·메뉴 설명·한국어 포함, `tests.js`의 `FORBIDDEN` 상수 하나에만): 기존 목록에 더해 `다이어트에 좋`, `다이어트 식품`, `저칼로리`, `칼로리가 낮은`, `살 안 찌`, `diet food`, `low-calorie`, `low calorie`, `slimming`, `fat-burning`, `低卡`, `减脂`, `瘦身`. `dietNote`를 포함해 어떤 문구도 이 검사를 통과해야 한다.
- 모든 사용자 문구는 `STRINGS[lang]`이나 메뉴 데이터에서 온다(HTML/JS에 직접 쓰지 않는다). localStorage 키는 `eik:history`, `eik:lastAnswers`, `eik:lang`이고, 읽기·쓰기는 `loadJSON`/`saveJSON`으로만 한다. 모드 선택은 저장하지 않는다(앱은 항상 첫 화면에서 시작).
- 모바일 우선 375px, 가로 스크롤 없음, 터치 대상 44px 이상. 모든 결과 화면에 `disclaimer`가 보인다.
- 메뉴 개수 기준(테스트): `dine` 79, `delivery` ≥ 40, `home` ≥ 25. 각 방식에서 제한 하나(`pork`/`vegetarian`/`seafood`/`nuts`, `spice "hot"`, `feel "any"`)만 켜도 `allowed`를 통과하는 메뉴가 ≥ 10개(`delivery`·`home`의 `vegetarian`은 ≥ 5). `light` 메뉴 ≥ 15개, `way "dine"`·`spice "hot"`·`feel "any"`에서 제한 하나만 켜도 `light` 메뉴가 ≥ 5개(`vegetarian`은 ≥ 3).
