# 외국인용 오늘 뭐 먹지 (가칭 eat-in-korea) — 설계 문서

작성일: 2026-11-03

## 1. 목적과 배경

- **문제**: 한국에 있는 외국인(유학생, 여행객)은 한글 메뉴판을 읽지 못하고, 어떤 재료가 들어가는지 몰라서 무엇을 먹을지 고르기 어렵다.
- **해결**: 못 먹는 재료와 매운 정도를 고르면 맞는 메뉴 하나를 골라주고, 식당에서 보여줄 한국어 카드와 근처 식당 검색까지 이어준다.
- **출발점**: 먼저 만든 '오늘 뭐 먹지' (`YangDongCheol/what-to-eat`)의 구조를 복사해서 별도의 새 앱으로 만든다. 두 앱은 대상과 문구가 달라서 합치지 않는다.
- **수익**: 지금은 범위에 넣지 않는다. 사용자가 생긴 뒤 여행객 대상 제휴(식당 예약 등)를 따로 검토한다.

## 2. 대상과 지원 언어

- 대상: 한국에 있는 외국인 유학생(중심)과 여행객.
- 지원 언어: **영어(en), 간체 중국어(zh)**. 앱 화면은 두 언어, 식당에 보여주는 카드는 한국어.
- 폰 언어가 `zh`로 시작하면 중국어, 아니면 영어로 시작한다. 상단에서 언제든 바꿀 수 있고 선택은 저장한다.
- 언어 추가는 `strings.js`와 메뉴 데이터에 번역을 더하는 것만으로 되도록 한다.

## 3. 성공 기준

- 앱을 열고 **10초 안에** 못 먹는 재료를 피한 메뉴 하나가 정해진다.
- 고른 제한에 걸리는 메뉴(돼지고기, 고기·생선, 해산물, 견과류)는 추천되지 않는다.
- 식당 직원에게 보여줄 한국어 카드와 지도 검색이 한 번의 탭으로 열린다.
- 제한을 하나만 골라도 추천할 메뉴가 충분히 남는다 (메뉴 수 기준은 10절 테스트 참고).

## 4. 범위

**포함**
- 질문 3개 → 조건에 맞고 최근에 고르지 않은 메뉴 1개 추천
- 결과 카드: 이모지, 현지어 이름, 한국어 이름, 읽는 법, 매운 정도, 보통 들어가는 재료, 설명
- 한국어 카드 화면, 구글 지도 검색 연결
- 고른 메뉴 기록(최근 3일 제외), 기록 보기·삭제
- 영어/간체 중국어 화면
- PWA: 홈 화면 설치, 오프라인 실행

**제외 (지금은 안 함)**
- 로그인, 서버, 기기 간 동기화
- 배달, 집밥(레시피), 혼자/여럿 구분
- 식당 정보·가격·리뷰 직접 조회, 메뉴 사진
- 소고기·계란·유제품·밀 제외, 번체 중국어 등 다른 언어
- 수익화 기능

## 5. 기술 선택

- 빌드 도구 없는 순수 HTML/CSS/JS PWA. 서버와 로그인 없음.
- 저장소: `localStorage` (브라우저 데이터를 지우면 기록도 사라진다).
- 배포: 새 GitHub 저장소 + GitHub Pages (공개 전에 사용자 확인을 받는다).
- 안드로이드 앱: `wte-android` 프로젝트와 같은 WebView 껍데기에서 주소와 패키지 이름만 바꿔서 만든다.

## 6. 화면 흐름

### 6.1 질문 화면
상단: 언어 전환(English / 简体中文). 모두 탭으로 답한다.

| 질문 | 선택지 | 방식 |
|---|---|---|
| 못 먹는 게 있나요? | 돼지고기 / 채식 / 해산물 / 견과류 | 여러 개 선택, 기본은 없음 |
| 매운 건 어때요? | 안 매운 것만 / 조금은 괜찮아요 / 매워도 좋아요 | 하나 선택, 기본은 안 매운 것만 |
| 어떤 게 당겨요? | 든든한 거 / 가벼운 거 / 상관없음 | 하나 선택, 기본은 상관없음 |

- 지난번에 고른 답이 미리 선택돼 있다. 화면 문구는 선택한 언어로 보인다.
- **[골라줘]** 버튼 → 결과 화면.

### 6.2 결과 화면
- 메뉴 카드: 이모지, 선택 언어의 이름(크게), 한국어 이름, 읽는 법, 🌶️ 개수(매운 정도 0~3), "보통 들어가는 재료" 표시, 설명 한두 줄.
- 안내 문구(항상 표시): 식당마다 재료가 다를 수 있으니 직원에게 확인하라는 내용.
- **[식당에 보여주기]** → 한국어 카드 화면.
- **[근처 식당 찾기]** → 구글 지도 검색을 새 탭으로 연다.
- **[다른 거]** → 같은 조건으로 다시 뽑는다. 이번 세션에서 이미 보여준 메뉴는 제외한다.
- **[← 다시 고르기]** → 질문 화면.
- **기록 저장**: [식당에 보여주기] 또는 [근처 식당 찾기]를 처음 누를 때 그 메뉴를 기록에 한 번만 저장한다 (같은 추천에서 두 번 눌러도 1개).

### 6.3 한국어 카드 화면
- 하얀 배경, 아주 큰 글씨의 전체 화면.
- 맨 위: 메뉴의 한국어 이름. 그 아래: `이거 1인분 주세요.`
- 고른 제한마다 한 줄씩 (7.3절의 문장을 그대로 쓴다).
- **[← 돌아가기]** 버튼으로 결과 화면에 돌아온다.

### 6.4 기록 화면
오늘 뭐 먹지와 같다. 최근 기록을 최신순으로 보여주고 항목별로 지울 수 있으며, 기록이 없으면 안내 문구를 보여준다.

## 7. 데이터와 로직

### 7.1 메뉴 데이터 (`menus.js`)
```js
{ id: "kimchi-jjigae", ko: "김치찌개", emoji: "🍲", rom: "Kimchi-jjigae",
  name: { en: "Kimchi Stew", zh: "泡菜汤" },
  desc: { en: "…", zh: "…" },
  spice: 2,                      // 0 안 매움, 1 약간, 2 매움, 3 아주 매움
  feel: "hearty",                // "hearty" | "light"
  contains: ["pork", "meat", "seafood"] }
```
- `contains`에 쓸 수 있는 값: `pork`(돼지고기), `meat`(돼지·소·닭 등 모든 고기와 고기 육수), `seafood`(생선·갑각류·조개·젓갈·멸치 육수), `nuts`(견과류·땅콩). 돼지고기가 들어가면 `pork`와 `meat`를 같이 적는다.
- **보수적으로 태그한다.** 그 음식에 흔히 들어가는 재료나 육수는 모두 태그한다.
- 채식을 골라도 충분히 나오도록 채식 가능한 메뉴(산채비빔밥, 야채김밥, 두부 요리 등)를 일부러 넣는다. 전체는 60~80개로 시작한다.
- `id`는 영문 소문자와 하이픈만 쓰고 서로 겹치지 않는다. 기록에는 `id`를 저장한다.

### 7.2 추천 로직 (`logic.js`, 순수 함수)
`pick(menus, answers, history, shown, now, rand = Math.random)` → `{ menu, cycled }`
- `answers = { restrictions: string[], spice: "none"|"mild"|"hot", feel: "hearty"|"light"|"any" }`
- `restrictions` 값은 `"pork"`, `"vegetarian"`, `"seafood"`, `"nuts"`.

1. **조건 거르기**
   - `pork` 제한 → `contains`에 `pork`가 있으면 제외.
   - `vegetarian` 제한 → `contains`에 `meat`나 `seafood`가 있으면 제외.
   - `seafood` 제한 → `contains`에 `seafood`가 있으면 제외.
   - `nuts` 제한 → `contains`에 `nuts`가 있으면 제외.
   - 매운 정도: `none` → `spice <= 0`, `mild` → `spice <= 1`, `hot` → 제한 없음.
   - 맛: `feel`이 `any`가 아니면 `menu.feel === feel`.
2. 거른 결과가 비어 있으면 `{ menu: null, cycled: false }`.
3. `shown`(이번 세션에 보여준 메뉴 id)에 있는 메뉴를 뺀다. 남는 게 없으면 `shown`을 비운 것으로 보고(`cycled: true`) 거른 결과 전체를 후보로 쓴다.
4. **최근 3일 제외**: 기록에서 `now - at < 72시간`인 메뉴를 후보에서 뺀다.
5. 후보가 있으면 무작위로 하나를 고른다.
6. 후보가 없으면(모두 최근에 먹음) 후보 중 **마지막으로 고른 시각이 가장 오래된** 메뉴를 고른다. 제한이 엄격해서 메뉴가 적은 사람이 막다른 길에 빠지지 않게 하기 위해서다. (오늘 뭐 먹지와 같은 규칙이다.)
- "조건에 맞는 메뉴가 없어요" 문구는 2단계(제한 조건 자체에 맞는 메뉴가 없을 때)에서만 나온다. 이때 "제한을 줄여 보세요"를 함께 안내한다.

### 7.3 한국어 카드 문장 (`logic.js`)
`staffCard(menu, restrictions)` → `{ dish: string, order: string, notes: string[] }`
- `dish`는 `menu.ko`, `order`는 `이거 1인분 주세요.`
- `notes`는 `restrictions`에 있는 항목마다 아래 문장 하나씩, 이 순서(돼지고기 → 채식 → 해산물 → 견과류)로 넣는다. 제한이 없으면 빈 배열.

| 제한 | 문장 |
|---|---|
| pork | 저는 돼지고기를 먹을 수 없어요. 돼지고기나 돼지고기 육수가 들어가나요? |
| vegetarian | 저는 채식을 해요. 고기, 생선, 고기 육수, 젓갈이 들어가나요? |
| seafood | 저는 해산물을 먹을 수 없어요. 생선, 새우, 조개, 젓갈이 들어가나요? |
| nuts | 저는 견과류와 땅콩을 먹을 수 없어요. 들어가나요? |

### 7.4 링크 (`logic.js`)
`mapsUrl(menu)` → `"https://www.google.com/maps/search/?api=1&query=" + encodeURIComponent(menu.ko + " 식당")`

### 7.5 화면 문구와 언어 (`strings.js`)
- `STRINGS = { en: {...}, zh: {...} }`. 두 언어의 키는 정확히 같아야 한다.
- `detectLang(navigatorLanguage)` → `"zh"` 또는 `"en"` (`zh`로 시작하면 `zh`, 그 외 `en`).
- 재료 태그, 매운 정도, 안내 문구도 모두 이 파일의 문구로 보여준다.

### 7.6 저장 (`localStorage`)
- `history`: `[{ id, at }]` (최근 100개), `lastAnswers`: `{ restrictions, spice, feel }`, `lang`: `"en"|"zh"`.
- 값이 깨졌거나 접근이 막히면 기본값으로 시작한다 (앱이 멈추지 않게). 저장된 값은 알려진 선택지와 알려진 메뉴 id만 받아들인다.

## 8. 안전 문구 원칙 (중요)

- 이 앱은 **일반적인 재료 기준 정보**만 준다. 식당마다 육수와 양념이 다르다.
- "할랄이에요", "알레르기 걱정 없어요", "안전해요"처럼 **보증하는 표현은 어디에도 쓰지 않는다.**
- 결과 화면에는 항상 "일반적으로 ○○가 들어가요. 식당에 꼭 확인하세요"라는 취지의 안내가 보인다. 한국어 카드의 질문 문장이 그 확인용이다.
- 알레르기는 생명과 관련될 수 있으니, 이 앱이 알레르기 대비를 대신하지 않는다는 점을 안내 문구에 명시한다.

## 9. 파일 구조
```
index.html      화면 4개 (섹션 전환)
style.css       모바일 우선 스타일, 따뜻하고 귀여운 톤 (what-to-eat 디자인 재사용)
app.js          화면 전환, 언어, 기록, 저장
logic.js        pick, staffCard, mapsUrl, 저장 헬퍼
menus.js        메뉴 데이터
strings.js      화면 문구 (en, zh), detectLang
manifest.json   PWA 이름·아이콘
sw.js           오프라인 캐시 (파일 바꿀 때마다 버전 올리기)
icon-192.png, icon-512.png
test.html, tests.js, run-tests.js   테스트
```

## 10. 테스트
브라우저에서 `test.html`을 열거나 `node run-tests.js`로 돌린다.
- `pick`: 돼지고기, 채식, 해산물, 견과류 제한이 각각 맞게 거르는지, 제한을 여러 개 섞었을 때, 매운 정도 제한, 맛 조건, "상관없음", 최근 3일 제외, 모두 최근이면 가장 오래전에 고른 메뉴, `shown` 제외와 순환, 맞는 메뉴가 없을 때 `null`.
- `staffCard`: 제한 없음 → `notes` 빈 배열, 제한마다 7.3절의 문장이 정확히 나오는지, 문장 순서.
- `mapsUrl`: 공백·특수문자가 들어간 이름이 인코딩되는지.
- `detectLang`: `zh-CN`, `zh-TW`, `en-US`, `ko-KR`, 빈 값.
- 메뉴 데이터: 개수 60~80, 필수 필드(영어·중국어 이름과 설명, 이모지, 읽는 법)가 비어 있지 않은지, `contains`와 `feel`, `spice` 값이 허용 범위인지, `id`가 겹치지 않는지. 돼지고기·해산물·견과류 제외를 각각 단독으로 골라도 메뉴가 20개 이상, 채식은 8개 이상 남는지.
- `strings.js`: 영어와 중국어의 키가 같은지, 빈 문구가 없는지.
- 저장 헬퍼: 깨진 값, 접근이 막힌 저장소, 100개 제한.
- 화면은 폰 크기(375px)와 실제 폰에서 직접 눌러 확인한다 (질문 → 결과 → 한국어 카드 → 기록, 언어 전환, 뒤로가기).

## 11. 배포와 남은 결정
1. 로컬에서 `index.html`을 열어 확인한다 (서비스워커는 `localhost`에서).
2. 새 GitHub 저장소를 만들고 Pages로 올린다. **공개 저장소를 만들기 전에 사용자에게 확인한다.**
3. 안드로이드 껍데기(WebView)로 APK를 만든다.

**아직 정하지 않은 것**: 앱 이름과 저장소 이름(현재 폴더 이름은 가칭), 아이콘 디자인, 중국어 번역을 확인해 줄 원어민.
